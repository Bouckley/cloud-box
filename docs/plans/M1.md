# M1 Box Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `boxd` on a laptop stores encrypted items end to end: setup, device login, pairing, resumable uploads, items and collections, sync, Trash, a first backup copy and a truthful safety status, all on the simulated HAL, so that an upload reaches `replicated` in a Go integration test.

**Architecture:** One SQLite database (`modernc.org/sqlite`, WAL) plus blob files under the data dir. Each domain package (`auth`, `blobs`, `library`, `trash`, `replica`, `status`) owns its SQL and takes a `*store.Store` and the `hal.HAL`; `api` maps HTTP to those services; `server` wires them and runs `jobs`. Item state is computed from `blobs` and `replicas` rows on every read, never stored, so it cannot go stale. TypeScript gains the ADR 0003 AD builders, client ids, the keyed BLAKE2b dedupe hash and the auth message, and a contract test drives a real `boxd` with the generated client and real encryption.

**Tech Stack:** Go 1.27 (`net/http`, `database/sql`), `modernc.org/sqlite`, `pgregory.net/rapid` (tests); TypeScript, Vitest, `libsodium-wrappers-sumo`, `openapi-typescript` + `openapi-fetch`, `undici` (contract test only).

**Spec:** `docs/10-roadmap.md` (M1 row), `docs/01-architecture.md`, `docs/03-security-and-encryption.md`, `docs/04-box-api.md`, `docs/05-storage-and-data-model.md`, `docs/06-hardware-abstraction.md`, `docs/08-testing-strategy.md`, ADR 0002, ADR 0003, `CLAUDE.md`.

## Design rulings (recorded in ADR 0004, Task 4)

- **Binary in JSON:** standard base64 with padding (Go's `[]byte` default). **Hashes:** lowercase hex (`sha256` of ciphertext, `dedupeHash`). **Ids:** 32 lowercase hex chars; user/device/collection/item ids come from the client (ADR 0003), upload and blob ids from the box.
- **Times:** RFC 3339 UTC in JSON; Unix milliseconds `INTEGER` in SQLite.
- **Auth message** (what a device signs): UTF-8 `cloudbox/v1/auth/<deviceId>/<challengeHex>`; challenge = 32 random bytes, hex, valid 60 s, single use.
- **Session token:** 32 random bytes, base64url without padding, sent as `Authorization: Bearer <token>`, stored only as SHA-256, valid 1 h. Pairing code: same format, stored hashed, valid 10 min, single use; issued by a signed-in device and carried in the QR.
- **Uploads:** part size 8 MiB (`8388608`), parts numbered from 0, every part except the last exactly 8 MiB, max blob 64 GiB, refused with `507 storage_full` when main-drive free space < size + 1 GiB. Abandoned uploads expire after 24 h.
- **Wrapped keys** are exactly 72 bytes (nonce 24 ‖ key 32 ‖ tag 16); `metadataEnc` 41 B–64 KiB; `nameEnc` 41 B–4 KiB. The box checks lengths only.
- **Item state** = the lowest state of its blobs: `stored` (row written), `verified` (re-read hash matched), `replicated` (a `replicas` row for target `backup` with `verified_at`). `uploading` is in the enum for apps but the box never returns it in M1, because items are created from completed uploads.
- **Sync:** global monotonic `seq`; every item insert/patch/trash/restore/replication bumps the item's `seq`; permanent deletion writes a tombstone with a new `seq`. `GET /v1/items?since=<cursor>&limit=<1..1000, default 500>`.
- **Errors** reuse M0's shape. Codes: `invalid_request` 400, `unauthorized` 401, `not_found` 404 (also for other users' objects), `id_taken`, `already_set_up`, `already_stored`, `blob_in_use`, `upload_incomplete`, `not_in_trash`, `last_device`, `rewrap_required`, `invalid_parent` (all 409), `payload_too_large` 413, `hash_mismatch` 422, `storage_full` 507, `backup_missing` (status warning), `internal_error` 500.

## Global Constraints

- Zero knowledge: request bodies carry only ciphertext, sizes, hashes and random ids. No endpoint accepts a plaintext name, date, location or key.
- Never log secrets: no `Authorization` header, session token, pairing code, challenge signature, request body or query string in any log line.
- Deletes go to Trash; permanent deletion only via `DELETE /v1/trash/{id}` (item must be trashed) or the 30-day purge.
- Safety status must be truthful: `replicated` only with a verified copy on the backup drive; `safe` is false while the backup drive is missing or anything is not yet copied.
- Hardware via `box/internal/hal` only; every interface has a `sim` implementation.
- Test first for box logic and crypto. Crypto changes keep `testdata/crypto-vectors.json` passing in Go and TS; existing vector sections stay byte-identical.
- API changes start in `api/openapi.yaml`; `make generate` then implement. CI's `check-generated` must stay green.
- Every query on items, collections, blobs and uploads is scoped by the session's user id; another user's object is `404`.
- Repo path contains spaces: quote every path in Make, scripts and tests (tests use a temp dir named `with space`).
- Commits: one or more per task, messages as given, no attribution trailers. Branch: `m1-box-core`.

## Review Focus

1. **Upload complete retried after the response was lost** must return the same `blobId` and not create a second blob → Task 9 test `TestCompleteIsIdempotent`.
2. **Parts sent out of order, re-sent, or the wrong size** must assemble to the exact ciphertext; a wrong-size part is rejected and not kept → Task 9 tests.
3. **A revoked device's token, an expired token, or another user's ids** must get `401`/`404` and never data → Tasks 7, 10, 12 tests.
4. **Backup drive unplugged after items were replicated** must make status `safe: false` with `backup_missing`, and `replica.Run` must mark nothing → Tasks 14, 15 tests.
5. **Items changing between sync pages** (created, trashed, purged mid-sync) must never be lost or duplicated in the client's view → Task 12 property test.
