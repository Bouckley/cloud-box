# 5. Storage and data model

SQLite holds metadata (mostly encrypted fields); encrypted blobs sit as files on
the main SSD. The backup drive gets a nightly copy of both.

## Disk layout (on the Pi)

```
/srv/cloudbox/                 Main SSD, ext4, mounted by UUID
├── db/box.sqlite              WAL mode
├── blobs/ab/cd/<blobId>       Encrypted blobs, sharded by id prefix
├── uploads/<uploadId>/        Chunks of uploads in progress
├── tls/cert.pem, key.pem      Self-signed certificate apps pin (key 0600); created once, never replaced
└── tmp/
/srv/cloudbox-backup/          Backup drive
├── db/box-YYYYMMDD.sqlite     Nightly snapshot (VACUUM INTO), keep 7
└── blobs/...                  Mirror of blobs/
```

On a laptop the same layout lives under `./.data/` in the repo (git-ignored).

## Tables

Schema: `box/migrations/0001_init.sql`, then `0002_m2.sql` (M2). Times are
Unix milliseconds (UTC).

| Table | Key columns | Notes |
|-------|-------------|-------|
| `users` | id, role, kdf_salt, kdf_ops, kdf_mem, master_key_password, master_key_recovery, recovery_public_key, identity_public_key, identity_key_enc, dedupe_key_enc | Wrapped keys only; `recovery_public_key` (unique, M2) checks recovery resets (ADR 0005) |
| `devices` | id, user_id, name_enc, sign_public_key, last_seen, revoked_at | |
| `sessions` | token_hash, user_id, device_id, expires_at | Token stored only as SHA-256 |
| `pairing_codes` | code_hash, user_id, created_by, expires_at, used_at | Single use, stored hashed |
| `collections` | id, owner_id, kind (album/folder), parent_id, name_enc, seq, deleted_at | `deleted_at` (M2): soft delete; the row stays because trashed items still need its key |
| `collection_keys` | collection_id, user_id, wrapped_key | One row per member |
| `items` | id, owner_id, device_id, collection_id, file_key_enc, metadata_enc, dedupe_hash, seq, trashed_at | `seq` drives sync; no stored state (see below) |
| `blobs` | id, owner_id, size, sha256 (of the ciphertext), stored_at, verified_at | |
| `item_blobs` | item_id, blob_id, role (original/preview/thumb) | A blob belongs to one item |
| `replicas` | blob_id, target (backup), copied_at, verified_at | Feeds "safe" status |
| `uploads` | id, user_id, device_id, size, sha256, part_count, created_at, expires_at, blob_id | `sha256` may be null until complete (M2: streaming clients send it then); `blob_id` set once complete, so a retried complete returns the same blob |
| `upload_parts` | upload_id, n, size | Which parts arrived |
| `tombstones` | item_id, owner_id, seq | Permanently deleted items, so sync can tell apps |
| `counters` | name, value | The global `seq` |
| `invites`, `links` (M7) | token_hash, collection_id, role, expires_at | Tokens stored hashed |
| `events` (M6/M7) | id, kind, at, detail | For the helper's activity view; no content |

`*_enc` columns hold XChaCha20-Poly1305 AEAD ciphertext
(`crypto_aead_xchacha20poly1305_ietf`, see ADR 0002) the box can't read.
A global monotonic `seq` increments on every change; clients sync with `since=seq`.

User, device, collection and item ids are generated by the client (16 random
bytes, hex) so they can be bound into ciphertext before upload, and
`items.file_key_enc` holds the wrapped file key; see
[ADR 0003](decisions/0003-associated-data-naming.md).

## Item state machine

```
uploading → stored → verified → replicated
                \______ trashed (any state) → purged after 30 days
```

An item's state is not stored: the box computes it on every read as the
lowest state of its blobs, so it can never go stale.

- `stored`: blob file written and fsynced.
- `verified`: box re-read the file and the hash matches.
- `replicated`: the copy on the backup drive exists and its hash matches.

## Jobs

| Job | When | What |
|-----|------|------|
| Replicate | Nightly at 02:00, and 10 min after a big upload | Copy new blobs and a DB snapshot to the backup drive |
| Scrub | Weekly | Re-hash a slice of blobs on both drives; flag mismatches |
| Trash purge | Daily | Delete items trashed more than 30 days ago and unreferenced blobs |
| Upload cleanup | Hourly | Remove abandoned uploads older than 24 h |
| Health | Every 15 min | Drive SMART, free space, temperature → status warnings |

## Migrations

Numbered SQL files in `box/migrations/`, applied at startup inside a transaction.
Never edit an applied migration; add a new one.
