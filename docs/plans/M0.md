# M0 Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A monorepo skeleton where `boxd` serves `GET /v1/health` over HTTPS, the API client is generated from OpenAPI, `@cloudbox/crypto` wraps libsodium, shared crypto vectors pass in TypeScript and Go, and CI runs all of it.

**Architecture:** Go module in `box/` (stdlib only for M0), TypeScript packages in a pnpm workspace consumed as TS source (no build step). `testdata/crypto-vectors.json` is generated once from the TS wrappers and committed; TS checks every section, Go checks only Ed25519 and SHA-256 (the only primitives the box uses).

**Tech Stack:** Go (stdlib `net/http`, `crypto/tls`, `crypto/ed25519`, `crypto/sha256`), Node LTS + pnpm, TypeScript strict, Vitest, ESLint (typescript-eslint flat config) + Prettier, `libsodium-wrappers-sumo`, `openapi-typescript` + `openapi-fetch`, GitHub Actions.

**Spec:** `docs/10-roadmap.md` (M0 row), `docs/02-repo-structure.md`, `docs/03-security-and-encryption.md`, `docs/06-hardware-abstraction.md` (`--hal` default), `docs/07-dev-setup.md`, `docs/08-testing-strategy.md`, `CLAUDE.md`, and the M0 brief from the user (items 1–7).

## Global Constraints

- Zero knowledge: nothing in M0 sends plaintext content, names, dates, locations or keys to the box.
- Never log secrets. Errors from `@cloudbox/crypto` carry no key, password or plaintext bytes.
- Hardware via the HAL only. M0 adds no hardware code; `--hal` is parsed and validated only.
- Box logic and crypto: test first (red → green → refactor).
- Crypto changes keep `testdata/crypto-vectors.json` passing in Go and TypeScript.
- API changes start in `api/openapi.yaml`; regenerate `packages/api-client`, then implement.
- Go module path: `github.com/Bouckley/cloud-box/box`. `go` directive = the installed Go version.
- TS: `"strict": true`, ESM only, Node `engines` `>=24`, `packageManager` pinned to the installed pnpm.
- Repo path contains spaces. Every Makefile/script path is quoted; `make` targets are verified from this checkout.
- Port 8443, data dir `./.data` (git-ignored), dev TLS files in `<data>/tls/`.
- Commits: one per task, message as given. No attribution trailers.

## Review Focus

1. **Password typed on a different keyboard** (`é` as one code point vs `e` + combining accent) must derive the same KEK → Task 6 test `deriveKek normalizes to NFC`.
2. **Truncated or extended file ciphertext** (last chunk dropped, bytes appended after the final chunk) must fail to decrypt, never return partial plaintext → Task 7 tests.
3. **Ciphertext moved to another item** by a malicious box (same key, different associated data) must fail → Task 6 test `aeadDecrypt rejects wrong ad`.
4. **Empty file and file exactly N × chunk size** must round-trip → Task 7 tests.
5. **boxd restart** must keep the same certificate (apps pin its fingerprint) and the private key must be `0600` → Task 3 tests.

### Task 6: Crypto ADR, doc 03 fix, KDF and AEAD wrappers

**Files:**

**Interfaces:**
- Produces:
  - `ready(): Promise<void>` (awaits `sodium.ready`; every other function throws `CryptoError("not_ready")` before it resolves).
  - `class CryptoError extends Error { code: "not_ready" | "invalid_input" | "decrypt_failed" }` — messages never include input bytes.
  - `type KdfParams = { opsLimit: number; memLimitBytes: number }`; `DEFAULT_KDF: KdfParams = { opsLimit: 3, memLimitBytes: 268435456 }`; `newSalt(): Uint8Array` (16 bytes); `deriveKek(password: string, salt: Uint8Array, params?: KdfParams): Uint8Array` (32 bytes).
  - `randomKey(): Uint8Array` (32); `aeadEncrypt(key, plaintext, ad): Uint8Array` returning `nonce(24) ‖ ciphertext‖tag(16)`; `aeadDecrypt(key, box, ad): Uint8Array`; `wrapKey(kek, key, ad)` / `unwrapKey(kek, wrapped, ad)` (32-byte keys only); `encryptMetadata(key, value: unknown, ad)` (JSON → UTF-8 → `aeadEncrypt`) / `decryptMetadata<T>(key, box, ad): T`.
  - Internal (not exported from `index.ts`): `aeadEncryptWithNonce(key, nonce, plaintext, ad)` for vector generation.

- [ ] **Step 1: ADR 0002 and doc 03.** Record the exact function per use:

  | Use | libsodium function |
  |---|---|
  | Password → KEK | `crypto_pwhash`, `ALG_ARGON2ID13`, 16-byte salt, ops 3 / mem 256 MiB stored next to the wrapped key |
  | Files | `crypto_secretstream_xchacha20poly1305_*`, 4 MiB plaintext chunks, `TAG_FINAL` on the last |
  | Metadata and key wrapping | `crypto_aead_xchacha20poly1305_ietf_encrypt/decrypt`, random 24-byte nonce, associated data required |
  | Sharing | `crypto_box_seal` / `crypto_box_seal_open` (X25519) |
  | Device login | `crypto_sign_detached` / `crypto_sign_verify_detached` (Ed25519); Go `crypto/ed25519` |
  | Upload integrity | `crypto_hash_sha256`; Go `crypto/sha256` |

  Why AEAD rather than `crypto_secretbox_easy`: secretbox is XSalsa20-Poly1305 (not XChaCha20 as doc 03 says) and has no associated data; AEAD binds each ciphertext to its item id or purpose so a malicious box cannot swap ciphertexts. `crypto_secretbox_xchacha20poly1305` exists only in sumo builds and also lacks AD.
