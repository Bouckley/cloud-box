# M2 Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app, served by `boxd`, that sets up the box with a recovery key, unlocks with a password, recovers with the recovery key, and lets the owner browse, upload, organise and safely delete photos and files, with a truthful safety banner on every main screen, so that journeys 1, 3, 4 and 8 pass in Playwright with axe.

**Architecture:** All client logic lives in a new platform-neutral package, `@cloudbox/core` (login, unlock, recovery, sync index, upload and download pipelines, library actions), so the M3 phone app reuses it unchanged. The web app (`web/`, React + Vite) is a thin UI over core plus three browser adapters: WebCrypto device keys in IndexedDB, Argon2id in a Web Worker, and canvas thumbnails. `boxd` gains the few endpoints M2 needs (setup presence, password change, recovery reset, collection delete, hash-at-complete uploads) and serves the built app from `go:embed` with a strict CSP.

**Tech Stack:** Go 1.27 (existing box); TypeScript 6, React 19, Vite, React Router 7, `@tanstack/react-virtual`, `exifr`, `qrcode` (matrix only), `@fontsource-variable/inter`, `@scure/bip39`; Vitest + Testing Library + jsdom; Playwright + `@axe-core/playwright`. Add each with `pnpm add` at its latest release on the day; the lockfile pins it.

**Spec:** `docs/10-roadmap.md` (M2 row), `docs/12-app-ui.md` and its linked designs (12 screens, UI research), `docs/03-security-and-encryption.md`, `docs/04-box-api.md`, `docs/08-testing-strategy.md` (journeys 1, 3, 4, 8), ADR 0002, ADR 0003, ADR 0004 (Known risks: recovery-key device reset), `CLAUDE.md`.

The roadmap row is one line; these decide what M2 contains. Each costs rework if wrong.

| # | Ruling | Why |
|---|--------|-----|

## Design rulings (recorded in ADR 0005, Task 1)

- **Recovery key:** 32 random bytes shown as 24 BIP39 English words (`@scure/bip39`, 256 bits + 8-bit checksum). Subkeys by `crypto_kdf_derive_from_key(32, id, "cbrecov1", entropy)`: id 1 = recovery wrap key (wraps the master key, AD `cloudbox/v1/user/<userId>/master-key/recovery`), id 2 = Ed25519 seed of the **recovery signing key**. Setup sends its public half; the box stores it as `users.recovery_public_key` (unique). Input accepts any case, extra whitespace, and 4-letter prefixes (BIP39 words are unique by 4 letters).
- **Recovery reset protocol:** `POST /v1/recovery/challenge {recoveryPublicKey}` → `{challenge, expiresAt}` (60 s, single use, unknown key `401`). `POST /v1/recovery/reset {recoveryPublicKey, challenge, signature, device}` where `signature` is the recovery key's Ed25519 signature of UTF-8 `cloudbox/v1/recover/<deviceId>/<signPublicKeyHex>/<challengeHex>` (the device key as lowercase hex, so a swapped key fails; changed after the Task 3 review) → `204`. In one transaction the box revokes every device of that user, deletes their sessions and pairing codes, and adds `device`. The client then logs in, unwraps the master key with the recovery key, sets a new password and names the device.
- **Password change:** `PUT /v1/account/password {kdf, masterKeyByPassword}` → `204`. The box cannot check the old password (zero knowledge); a signed-in device can replace the wrap. Accepted: the recovery key still unwraps the master key (ADR 0005 Known risks).
- **Device names are optional at pairing.** `POST /v1/devices/pair` and `/v1/recovery/reset` take `device.nameEnc` as optional, because a new device has no master key yet. The box stores an empty blob; `Device.nameEnc` is `null` until the device sets it with `PATCH /v1/devices/{id} {nameEnc}` (own user's devices only; another user's is `404`).
- **Uploads take the hash at the end.** `POST /v1/uploads {size, sha256?}`; `POST /v1/uploads/{id}/complete {sha256?}`. Exactly one of them must carry it (neither: `400 invalid_request`; both and different: `400 invalid_request`). Why: a streaming client hashes ciphertext as it encrypts and uploads, and secretstream encryption is randomised, so the hash is not known before the last part. `Upload.sha256` is `null` until known.
- **Box info:** public `GET /v1/info` → `{setUp, setupOpen, version}`, so a new browser knows whether to show setup or connect.
- **Collection delete is soft.** `DELETE /v1/collections/{id}` → `204` only when no untrashed item and no undeleted child collection is in it, else `409 collection_not_empty`. It sets `deleted_at` and bumps `seq`. `GET /v1/collections` still returns deleted ones (with `deletedAt`), because trashed items need their collection key. Restoring an item un-deletes its collection and every deleted ancestor. When the last item in a deleted collection is permanently deleted or purged, the collection row and its keys go too, then the same check runs on its parent. Creating or moving into a deleted collection is `404`.
- **Plaintext formats (all inside AEAD ciphertext, AD per ADR 0003):**
  - Collection name: UTF-8 JSON `{"v":1,"name":"Family","role":null}`; `role` is `"photos"` (the default photo library, kind `album`) or `"files"` (the Files root, kind `folder`) for exactly one collection each. The client creates both right after setup, and on unlock if either is missing.
  - Item metadata: UTF-8 JSON `{"v":1,"name","mime","size","modifiedAt","takenAt","width","height","durationMs","favourite","thumbMime","previewMime"}`. Times RFC 3339; unknown values `null`.
  - Device name: UTF-8 text, at most 64 characters.
- **Classification:** an item is a *photo* when its collection's kind is `album`; Videos is photos whose `mime` starts `video/`. Files shows items in `folder` collections. The timeline sorts by `takenAt ?? modifiedAt`, newest first, grouped in the browser's time zone.
- **Thumbnails and previews (client):** thumb = longest side 320 px, WebP quality 0.8; preview = longest side 2048 px, JPEG quality 0.85; EXIF orientation applied. Made for every image the browser can decode; videos get a thumb from the frame at 0.5 s. If decoding fails, the item has the original only and shows a file tile.
- **Upload pipeline (client):** read the file once to compute the dedupe hash and look it up (`already on your box` or `in Trash` stops here), then generate the item id and file key, encrypt in 4 MiB chunks, buffer 8 MiB parts, hash the ciphertext incrementally and PUT each part as it fills, then complete with the hash. One file at a time; parts retried 3 times with backoff 1 s, 4 s, 10 s. A reload loses an in-flight upload (the box expires it after 24 h).
- **Session expiry:** core retries a request once after a `401` by logging in again with the device key (not for `/v1/auth/*`). A second `401` means the device was revoked.
- **Web security headers** on every app response from `boxd`: `Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' blob:; media-src 'self' blob:; worker-src 'self' blob:; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`, plus `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`. Fonts are self-hosted (no Google Fonts: the box works offline and leaks nothing).
- **New error codes:** `press_button` 409, `collection_not_empty` 409. Client-side errors (`ClientError.code`): `wrong_password`, `wrong_recovery_key`, `recovery_words`, `not_paired`, `revoked`, `box_unreachable`, `kdf_limits`.

## Global Constraints

- Zero knowledge: requests carry only ciphertext, sizes, hashes and random ids. No plaintext name, date, location, password or key reaches the box, and none is stored in browser storage (only the device key, as a non-extractable `CryptoKey`).
- Never log secrets: no recovery words, passwords, keys, tokens or decrypted metadata in `console.*`, Go logs, Playwright traces attached to CI, or error messages.
- Deletes go to Trash; permanent deletion only from Trash (with a confirm) or the 30-day purge.
- Safety status must be truthful: "safe" wording only when `/v1/status` says `safe: true`; an item reads "Safe" only when its `state` is `replicated`.
- Hardware via the HAL only (the setup button uses `hal.PowerButton`); every interface keeps its sim.
- Accessibility: WCAG 2.2 AA on every screen (axe with tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`, zero violations), 48 px minimum targets, a label on every control, keyboard operable, visible focus, `prefers-reduced-motion` respected, status shown with icon + words (never colour alone), no time limits or auto-dismissing errors, text usable at 200% zoom with no horizontal scroll at 320 CSS px.
- Design tokens (doc 12): safe `#2E7D5B`, safe tint `#E6F1EB`, attention `#E0A33A` on `#FBF0D9` text `#3B2800`, danger `#B3261E`, text `#16181B`, secondary `#5C6066`, page `#F4F4F1`; Inter; body 17 px.
- API changes start in `api/openapi.yaml`; `make generate`; CI's `check-generated` stays green.
- Crypto changes keep `testdata/crypto-vectors.json` passing in Go and TS; existing sections stay byte-identical (only additions in the diff).
- Test first for box logic, crypto and core. Every box query stays scoped by the session's user; another user's object is `404`.
- Quote every path (the repo path has spaces); Go tests use a temp dir named `with space`.
- Commits: one or more per task, messages as given, no attribution trailers. Branch: `m2-web-app`.

## Review Focus

1. **Session expires during a long upload or an idle tab** (1-hour tokens): the next request logs in again and carries on; the upload is not lost → Task 8 test `TestReloginAfterExpiry` (core) with the sim clock advanced 61 minutes mid-upload.
2. **The same photo uploaded twice, or one already in Trash:** no second item, no error; the user sees `Already on your box` or `In Trash` with Restore → Task 10 tests `duplicate is skipped`, `trashed duplicate offers restore`.
3. **Recovery words typed imperfectly:** capitals, extra spaces or line breaks, 4-letter prefixes are accepted; a wrong word or wrong count names the problem; valid words from another box say `Those words don't match this box.` and never crash → Task 7 and Task 8 tests.
4. **A library of 10,000 photos:** sync pages until done, and the timeline renders only visible tiles → Task 9 test `syncs every page`, Task 13 test `renders a 10,000-photo timeline with under 300 tiles in the DOM`.
5. **Backup drive unplugged after everything was safe:** every main screen's banner switches to `Backup copy paused` within one status poll, and no item reads "Safe" text in the viewer while the warning stands → Task 17 E2E `backup-paused.spec.ts`.
